### 2.3 最高速度の定数を下げても速度差はほとんど出ない

単独走行（干渉なし）で 2 周目を測った。**基準は「自機スペック・理想ライン」の 66.69 m/s**。

| 変更 | 走行中の最高速度 | 基準との比 | ラップ |
| --- | --- | --- | --- |
| 無し（自機スペック） | 66.69 m/s | 1.000 | 69.900 s |
| `MAX_SPEED` を 74.1（= 78 × 0.95）へ | 64.77 | **0.971** | 70.617 |
| `MAX_SPEED` を 72 へ | 63.67 | 0.955 | 71.033 |
| `MAX_SPEED` を 70 へ | 62.55 | 0.938 | 71.433 |

最長直線は 434 m しかなく、0 → 74.1 m/s には 1,132 m 要る（§2.1）。つまり
**`MAX_SPEED` は「終速の上限」としてはこのコースで一度も効かず、加速の鈍り方としてしか効かない**。
定数を素直に 0.95 倍しても、実際に出る速度の比は 0.971 にしかならない。これが案 B を採る理由。

### 2.4 案 B の較正 — 速度スケール `k` を実測で決める

`MAX_SPEED` と `ACCEL` の**両方**を `k` 倍すると、直線加速の速度が常に `k` 倍の車になる
（`dv/dt = kA(1 − v/kV)` は `v → kv` で元の式に一致する）。`k` を振って実測比を測った。

| k | `MAX_SPEED` | `ACCEL` | 走行中の最高速度 | 基準との比 | ラップ | 立ち上がりの損 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.930 | 72.54 | 10.23 | 63.24 m/s | 0.9482 | 71.567 s | +2.650 s |
| 0.932 | 72.70 | 10.25 | 63.31 | 0.9493 | 71.517 | +2.633 |
| **0.933** | **72.77** | **10.26** | **63.39** | **0.9505** | **71.483** | **+2.650** |
| 0.934 | 72.85 | 10.27 | 63.40 | 0.9507 | 71.500 | +2.617 |
| 0.940 | 73.32 | 10.34 | 63.75 | 0.9560 | 71.333 | +2.633 |

**`SPEED_SCALE = 0.933`**。このとき実測比はちょうど 0.950 になる。

### 2.6 「理想」と「普通」— `LEADER_LAP_SECONDS` の 2 つのアンカー

| **普通** | **74.68 s** | ペース 0.90 相当（コーナーごとに 1 割の余裕を持たせた走り）＋ 反応遅れ 6 tick ＋ ライン誤差 1.5 m の実測値 |

## 3. 要求の解釈と決定

| # | 論点 | 決定 |
| --- | --- | --- |
| D-1 | 「目標タイム」はラップか総レース時間か | **総レース時間**（GO から完走まで）。順位は総時間で決まるため。実装は 1 周の目標から導く |
| D-2 | 「最高速度 0.95」の解釈 | **案 B — 走行中に実際に出る最高速度の比を 0.95 にする**。`MAX_SPEED` と `ACCEL` をともに `SPEED_SCALE` = 0.933 倍する（§2.4）。定数を 0.95 倍する案 A は実測比が 0.971 にしかならず、直線で並んでも自機がほとんど前に出ないため採らない |
| D-3 | +2 秒のばらつきの掛かり先 | **総レース時間の目標に一様分布で 0〜+2.0 秒**を足す |
| D-4 | 「15 秒差」は目標値か実測値か | **目標値**。全車が目標を達成すれば実測も 15 秒差になる。ばらつき（D-3）と渋滞で実測は前後する。テストは「目標値は厳密に 15 秒差」「実測は 15 ± 3 秒」で固定する |
| D-5 | 15 秒差は敵車 7 台の中の差か、自機を含めた 8 台か | **敵車 7 台の中**。自機のタイムは操作次第で決まるので設計値を置けない |
| D-6 | 遅れた車が目標へ追いつくための「ゴム紐」を許すか | **許さない**。ペース倍率の上限は 1.0（＝その車の限界）とし、事故で失った時間は取り返せない。目標タイムは**上限ではなく設計値**である |
| D-7 | 難易度 | **`DIFFICULTY` テーブルへ切り出す**（§4.3）。既定は `normal`。画面からの選択 UI は本フェーズの範囲外で、テーブルと `createRaceState()` の口だけ先に用意する |

## 4. 設計

### 4.1 データ構造（`sim/state.ts`）

`CarState` の AI 個体差を差し替える。

```ts
// ── 車ごとの能力（生成時に決まり、以後変わらない）
/** 速度モデル全体に掛かる倍率。自機は 1、敵車は BALANCE.SPEED_SCALE */
readonly speedScale: number;
/** 目標総レースタイム [tick]。GO から完走まで。目標を持たない車は -1 */
readonly targetRaceTicks: number;
/** 理想ラインの横方向オフセット [m]（据え置き） */
readonly lineBias: number;
/** 反応の鈍さ [tick]（据え置き） */
readonly reactionTicks: number;

// ── ペース制御の状態（毎ティック更新される派生値）
/** 現在のペース倍率。AI の目標速度に掛かる */
pace: number;
```

`skill` は**廃止**し `pace` が置き換える。`skill` は乱数で決まる固定値だったが、
`pace` は目標タイムから毎ティック逆算される値になる。参照箇所は `sim/ai.ts` と
`sim/state.ts` だけなので、他は影響を受けない（`view/` からの参照は無い）。

速度の 2 定数は車ごとの値を返す小さな関数で取り出す（`vehicle.ts`）。

```ts
export function topSpeedOf(car: CarState): number { return VEHICLE.MAX_SPEED * car.speedScale; }
export function accelOf(car: CarState): number { return VEHICLE.ACCEL * car.speedScale; }
```

**乱数列の互換**: `createCar()` の `rng.next()` は既存の 2 回（`lineBias` / `reactionTicks`）の
**後ろへ** 目標タイムのばらつきを足す。こうすると既存のライン個体差が変わらず、
差分の原因を速度スケールと目標タイムだけに絞れる。

`hashRaceState()` は変更しない（`speedScale` / `targetRaceTicks` は定数、`pace` は
`speed` と `s` に必ず現れるため、決定性はいまのハッシュで十分に捕まる）。

### 4.2 最高速度（R-1 / 案 B）

```ts
/** 敵車の速度モデルに掛かる倍率。走行中の最高速度が自機の 0.950 倍になる値（§2.4 の実測） */
SPEED_SCALE: 0.933,
```

| 箇所 | 現在 | 変更後 |
| --- | --- | --- |
| `vehicle.ts` `stepVehicle` の目標速度 | `VEHICLE.MAX_SPEED * throttle` | `topSpeedOf(car) * throttle` |
| `vehicle.ts` `stepVehicle` の加速 | `VEHICLE.ACCEL * (1 - car.speed / VEHICLE.MAX_SPEED)` | `accelOf(car) * (1 - car.speed / topSpeedOf(car))` |
| `ai.ts` `targetSpeedFor` の初期値 | `VEHICLE.MAX_SPEED` | `topSpeedOf(car)` |

> **コードに 0.95 と書かない。** `SPEED_SCALE` は 0.933 であり、0.95 は**その結果として
> 実測される比**である。この 2 つを取り違えないよう、定数のコメントと §6 の較正ツール、
> テスト（§7.1 の 1）は必ず「実測比」を主語にする。コースを変えたら `SPEED_SCALE` は測り直す。

`cornerSpeedLimit()` の直線時の戻り値（`VEHICLE.MAX_SPEED`）は「上限なし」を意味する
番兵なので触らない。`ai.ts` 側で `topSpeedOf(car)` と `Math.min` が取られる。

`view/` と `audio/` は `VEHICLE.MAX_SPEED` を**自機の速度計の正規化**にしか使っておらず
（`camera.ts` / `tachometer.ts` / `engine-sound`）、いずれも自機だけを見るので変更不要。
`module.ts:102` の `maxSpeed: VEHICLE.MAX_SPEED` だけは意味を明確にするため
`topSpeedOf(player)` へ変える（値は同じ）。

**案 B の副作用（意図したもの）**: `ACCEL` も 0.933 倍になるので、**コーナー立ち上がりでも
自機が前に出る**。立ち上がりの損は 2.5 → 2.65 秒に増える。逆に副作用ではない点として、
コーナリング速度はグリップで決まるため変わらない（R-1 は最高速度の要求であり、
コーナーを遅くする要求ではない）。

### 4.3 目標タイムの割り当て（R-2 a/b/c）と難易度テーブル（D-7）

```ts
export type Difficulty = 'easy' | 'normal' | 'hard';

export const DIFFICULTY: Record<Difficulty, { leaderLapSeconds: number; fieldSpreadSeconds: number }> = {
  //                          先頭の目標ラップ   トップ〜最下位の差
  easy:   { leaderLapSeconds: 74.7, fieldSpreadSeconds: 15 },
  normal: { leaderLapSeconds: 72.3, fieldSpreadSeconds: 15 },
  hard:   { leaderLapSeconds: 71.9, fieldSpreadSeconds: 15 },
};

const BALANCE = {
  SPEED_SCALE: 0.933,                 // §4.2
  STANDING_START_SECONDS: 2.65,       // §2.4 の実測
  START_JITTER_SECONDS: 2,            // R-2 (b)
} as const;
```

**`normal` の 72.3 秒は §2.6 の 2 つのアンカーの中間値**（理想 69.90 と普通 74.68 の平均 = 72.29）。
`easy` は「普通」そのもの、`hard` は AI の限界（§2.5 の 71.48 秒）に 0.4 秒だけ足した値。

> **`hard` をこれ以上速くできないのは R-1 の帰結**である。`SPEED_SCALE` = 0.933 の車の
> 限界ラップが 71.48 秒なので、`leaderLapSeconds` は 71.6 秒より下へ行けない。
> さらに速い難易度が要るなら、R-1（0.95）を緩めるしかない（§8 リスク 2）。

敵車 `entrant` = 1..7 に対し、**グリッド順（前ほど速い）**で目標を配る。

```
rank            = entrant - 1                                         // 0..6
lapSeconds      = leaderLapSeconds + rank * (fieldSpreadSeconds / LAP_COUNT) / 6
raceSeconds     = LAP_COUNT * lapSeconds + STANDING_START_SECONDS + rng.next() * START_JITTER_SECONDS
targetRaceTicks = Math.round(raceSeconds * 60)
```

きざみは `15 / 3 / 6` = **0.8333 秒/周**。`normal` の目標は次のとおり
（必要ペースは §2.5 の較正 `1 + (71.48 − lap) / 49.85` から）。

| entrant | 目標ラップ | 目標レース（ばらつき前） | 必要ペース |
| --- | --- | --- | --- |
| 1 | 72.300 s | 219.6 s | 0.984 |
| 2 | 73.133 | 222.1 | 0.967 |
| 3 | 73.967 | 224.6 | 0.950 |
| 4 | 74.800 | 227.1 | 0.933 |
| 5 | 75.633 | 229.6 | 0.917 |
| 6 | 76.467 | 232.1 | 0.900 |
| 7 | 77.300 | 234.6 | 0.883 |

**トップと最下位の差 = 234.6 − 219.6 = 15.0 秒**（要求どおり）。

難易度ごとの端の値と、ペース制御に必要な範囲。

| 難易度 | 先頭の目標レース | 最下位の目標レース | 先頭の必要ペース | 最下位の必要ペース | 先頭の余裕 |
| --- | --- | --- | --- | --- | --- |
| easy | 226.8 s | 241.8 s | 0.935 | 0.835 | 9.7 s |
| **normal** | **219.6** | **234.6** | **0.984** | **0.883** | **2.5 s** |
| hard | 218.4 | 233.4 | 0.992 | 0.891 | 1.3 s |

「先頭の余裕」は**限界（217.1 秒 = 3 × 71.483 + 2.65）との差**であり、渋滞や小さなミスを
取り返せる量にあたる。`normal` の 2.5 秒はレース全体での余裕なので、1 周あたり 0.8 秒。

### 4.4 ペース制御（R-2 d）

閉ループ。**残り距離と残り時間から必要な平均ラップタイムを出し、それをペース倍率へ写す。**
`sim/ai.ts` に置き、`driveAi()` の先頭で毎ティック更新する。

```ts
const PACE = {
  /** ペース 1.0 で走ったときの 1 周 [s]。§6 の較正ツールが出す（§2.5 の実測） */
  REFERENCE_LAP_SECONDS: 71.48,
  /** ペース 1 あたりのラップタイムの変化 [s]。同上 */
  SECONDS_PER_PACE: 49.85,
  /** ペースの下限。easy の最下位（0.835）を含められる値 */
  MIN: 0.80,
  /** 上限 1.0 が D-6（ゴム紐なし）そのもの */
  MAX: 1.0,
  /** 目標ペースへ寄せる速さ [1/s]。急な加減速に見えない程度に鈍くする */
  RESPONSE: 0.7,
} as const;
```

```
elapsedSeconds   = tickToSeconds(state.tick - COUNTDOWN_TICKS)
remainingMeters  = LAP_COUNT * track.length - car.progress
remainingSeconds = tickToSeconds(car.targetRaceTicks) - elapsedSeconds
requiredLap      = remainingSeconds > 0
                     ? remainingSeconds * track.length / remainingMeters
                     : 0                                  // 予定より遅れている → 全力
wanted           = 1 + (REFERENCE_LAP_SECONDS - requiredLap) / SECONDS_PER_PACE
car.pace        += (clamp(wanted, MIN, MAX) - car.pace) * RESPONSE * dt
```

- `car.progress` は**スタートラインからの走行距離**（`race.ts` の定義で、ライン通過時に 0）。
  グリッド後方の車は `progress` が負から始まるので、**余分に走る距離が自動的に目標へ織り込まれる**
- `targetSpeedFor()` の末尾は `* car.skill` から `* car.pace` へ変わるだけ
- `pace` の初期値は `wanted` の初回値（＝立ち上がりでいきなり加減速しない）
- カウントダウン中と完走後は更新しない。`targetRaceTicks < 0` の車（実操作の自機）も更新しない

**この方式を選ぶ理由**: 開ループ（目標タイム → ペース を最初に 1 回だけ決める）だと、
渋滞・接触・コースアウトで狂ったぶんがそのまま最終タイムの誤差になり、15 秒差が崩れる。
閉ループなら「遅れたら少し詰める・進みすぎたら少し緩める」が自然に出る。上限 1.0 が
あるので、ゴム紐にはならない。

§2.5 の線形近似は**先読み（フィードフォワード）にしか使っていない**ので、近似誤差
（測定点で最大 0.3 秒）は閉ループが吸収する。較正がずれても目標には届く。

### 4.5 自機の扱い

| 場面 | `speedScale` | 目標タイム |
| --- | --- | --- |
| 実走行（`autoPilot: false`） | 1（＝ `MAX_SPEED` 78） | 無し（`-1`）。ペース制御は動かない |
| アトラクトデモ（`autoPilot: true`） | 1 | **中位の目標（entrant 4 相当 = 227.1 s）を与える** |

アトラクトデモで自機だけ目標無し（＝常に全力）にすると、ポールスタートと相まって
**デモが毎回同じ独走**になる。中位の目標を与えると、ポールから順位を下げてから
中盤で競る画になる。自機のスペック（速度スケール 1）は変えない — デモは「自機の車」を
見せる場なので。

## 6. 較正ツール `tools/measure-pace.mjs`

§4.2 の `SPEED_SCALE`・§4.4 の `REFERENCE_LAP_SECONDS` / `SECONDS_PER_PACE` は
**コース形状と車両定数から決まる実測値**なので、定数を手で書くのではなくツールで出す。
`sim/` を直接 import して次を行う。

1. 自機スペック・ペース 1.0 で 1 台だけ走らせ、**基準の最高速度**（現状 66.69 m/s）と
   **理想ラップ**（69.90 s）を測る
2. `SPEED_SCALE` を二分探索し、**走行中の最高速度の比がちょうど 0.950 になる値**を求める
   （§2.4）。得られた値と現在の定数がずれていたら警告する
3. その車のペースを 0.80〜1.00 で振り、`REFERENCE_LAP_SECONDS` と最小二乗の傾き
   `SECONDS_PER_PACE` を出す
4. 立ち上がりの損（1 周目 − 2 周目）を測り、`STANDING_START_SECONDS` を出す
5. 難易度ごとに §4.3 の目標表と必要ペースを出し、**必要ペースが `PACE.MIN`〜`MAX` を
   外れたら異常終了**する（＝到達不能な目標を弾く）

`npm run measure:pace` として `package.json` に登録する。速度定数・コース・AI のライン計算を
変えたら必ず流す。

**`leaderLapSeconds` の調整手順**（§2.6 の「普通」アンカーの検証）:
実際に 3 周走ってベストラップを記録し、それを「普通」のアンカー（仮値 74.68 秒）と
差し替えて `normal` を「理想と実測の中間値」に置き直す。`easy` は実測そのもの、
`hard` は AI の限界 + 0.4 秒のままとする。
