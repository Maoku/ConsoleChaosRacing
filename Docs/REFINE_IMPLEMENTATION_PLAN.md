## 2. 現状の実測

### 2.1 第2世代の車の色（R-1）

`public/assets/gen2/sprites/car_frames.png` を画素ごとに数えた。

| 行 | 何の車か | 固有色数 | 彩度 > 0.35（＝車体色）の色数 | 無彩色寄りの色数 |
| --- | --- | --- | --- | --- |
| 0 | 自機（黄） | 125 | 75 | 50 |
| 1 | ライバル（赤） | 110 | 60 | 50 |

- アトラスは 3 列 × **2 行**（`CAR_SPRITE_GEOMETRY.rows = 2`）。**8 台が黄と赤の 2 色しか無い**
- 実機の SFC スプライトは**1 パレット 16 色**（本プロジェクトは BG も 8×8 タイル 16 色で揃えており、
  `tests/road-texture.spec.ts` が遠景に対して固定している）。**車だけがこの規約から外れている**
- 画面の同時色数の実測は **207 色 / 256**（`Docs/QUALITY_REVIEW.md` §2）。ここに 8 色ぶんの
  車体色を足すので、**パレットを絞らずに 8 種類へ増やすと 256 色を超える**
- 第3・第4世代は `ENTRANT_COLORS`（8 色・色相を均等に散らした表）を `MeshCommand.color` の
  乗算で使う。ミニマップのマーカーも同じ表を読む。**第2世代だけがこの表に参加していない**

### 2.2 車スプライトの重ね順（R-2）

AI 8 台のデモを完走まで回し、6 ティックごとに第1・第2世代のフレームを組み立てて、
**車スプライトが画面上で重なっているフレーム**の重ね順を調べた（2,334 フレーム）。

| 世代 | 車が重なるフレーム | うち重ね順が Y と逆 | 最大の食い違い |
| --- | --- | --- | --- |
| FC | 691 | **52（7.5 %）** | 58.7 px |
| SFC | 1,137 | **182（16.0 %）** | 52.0 px |

原因は 2 つある。

1. `rivalPlacements()` は**遠い順**に返し（コメントも「近い車が後 ＝ 手前に描かれる」と書いている）、
   一方 `pushSpritePlane()` は「登録順＝優先度」の実機規約に合わせて**逆順に積む**。
   結果として**遠い車が手前**に出る
2. 自機は必ず先頭に登録されるので、**自機より近いライバル（カメラと自機の間にいる車）も
   自機の後ろに描かれる**（実測: tick 2400 でライバルの絵が 103.9 px、自機が 100.3 px ＝
   ライバルのほうが近いのに奥に描かれている）

**走査線制限は今のところ 1 件も効いていない**（FC・SFC とも 2,334 フレームで落ちた件数 0）。
Y 順に積み替えても、制限で自機が消える心配はいまのコースでは無い（§3 の D-3）。

| --- | --- |
| 車体が重なっているティック | **739 / 14,442（5.1 %）** |
| 重なりの事象（連続を 1 回と数える） | **5 回** |
| 壁への接触 | **0 ティック**（AI は路外へ出ない。フェーズ 9-1 の記録どおり） |

### 2.4 壁とタイヤ壁（R-4）

| 項目 | 実測 |
| --- | --- |
| シムの壁 | `halfWidth + VEHICLE.RUNOFF` ＝ 中心線から **15.0 m**（`halfWidth` は 6.0〜6.2 m） |
| 描かれる壁（コースメッシュ） | `halfWidth + CURB_WIDTH(1.2) + GRASS_WIDTH(9)` ＝ **16.2 m** |
| タイヤフェンス | 33 基。`halfWidth + 3` ＝ **9.0〜9.2 m**。**当たり判定は無い**（素通りする） |
| 背景オブジェクト全体 | 244（タイヤ 33 / 看板 11 / 木 200） |

**シムの壁は、描かれている壁より 1.2 m 手前にある。** メッシュ側のコメントは
「草地の幅は `VEHICLE.RUNOFF` と揃える」と書いてあるが、縁石 1.2 m を足し忘れている。

壁への当たりの強さ（直線・60 m/s・全開で壁へ寄せ、接触した 1 ティックの速度損）:

| 当たり方（ヨー角） | 接触時の速度 | 1 ティックの損 | 3 秒後の速度 |
| --- | --- | --- | --- |
| 掠り（0.05） | 50.9 m/s | **−0.50 m/s** | 45.5 m/s |
| 接触（0.2） | 57.7 | −10.95 | 36.4 |
| 激突（0.5） | 58.7 | −41.41 | 17.5 |

**「大幅減」になっていないのは掠りだけ**（−0.5 m/s ＝ 1 %）。激突は既に十分に効いている。
音は `sfx.ts` が `hitWall` で 1 発鳴らしており、**材質の区別が無い**。
参考: タイヤ壁がある位置（草地 3 m）を 60 m/s で 1 秒走ると 54.6 m/s まで落ちるだけで、
**いまは「タイヤ壁を通り抜けて草地を走る」ほうが速い**。

### 2.7 CRT と画面モード（R-7）

エンジンの CRT は**1 本のシェーダ ＋ 7 つの uniform**で、値は信号系統ごとのプリセット。

| 信号（世代） | scanline | bleed | **curvature** | bloom | vignette | noise | **mask** |
| --- | --- | --- | --- | --- | --- | --- | --- |
| rf（FC） | 0.32 | 0.85 | **1.00** | 0.35 | 0.55 | 0.055 | **0.50** |
| composite（SFC） | 0.28 | 0.55 | **0.85** | 0.28 | 0.45 | 0.025 | **0.42** |
| svideo（PS1） | 0.22 | 0.25 | **0.60** | 0.20 | 0.35 | 0.012 | **0.30** |
| component（PS2） | 0.14 | 0.08 | **0.35** | 0.14 | 0.22 | 0.004 | **0.18** |

- `uCurvature` は樽型歪み（`curve()`）。**これが「ブラウン管の丸み」そのもの**
- `uMask` は蛍光体マスクで、シェーダは `mod(gl_FragCoord.x, 3.0)` ＝ **出力画素の 3 本周期の縞**を
  掛ける。表示側の画素格子と干渉して**うなり（モアレ）に見える主因はこれ**。
  走査線（`uScanline`）も画素周期の縞なので、**「モアレ OFF」ではこの 2 つをまとめて切る**（D-13）
- 走査線のほうは**エンジンが既にモアレ対策済み**である。シェーダのコメントが
  「内部解像度で本数を数えると本ごとに太さが揺れる ＝ 画面全体にうなり（モアレ）が出る。
  丸めておけばどの本も同じ太さになり、うなりが消える」と書き、
  `thickness = floor(outputHeight / contentHeight + 0.5)` で出力画素の整数倍に固定している
- `crtOverride?: () => Partial<CrtPreset>` は**毎フレーム評価される**（`createCrtPasses` の
  `uniforms()` から呼ばれる）。実行時に切り替えてもレンダラーを作り直す必要は無い
- いま `bootstrap.ts` が使っているのは開発時の `?crt=off` だけ（全項目 0 の `FLAT_CRT`）

## 3. 要求の解釈と決定

| # | 論点 | 決定 |
| --- | --- | --- |
| D-1 | R-1 を「パレット替え」でどう実装するか | **アトラスに 8 行を焼く。8 行はすべて同じインデックス地図を共有し、パレット（16 色）だけが違う。** 実機の「1 タイルセット + 8 パレット」に対応する。実行時の乗算（`SpriteCommand.color`）は採らない — 元絵が赤なので緑を掛けると黒く沈み、タイヤや窓まで染まる（第3世代が無彩色テクスチャを焼いたのと同じ理由） |
| D-2 | 第1世代（FC）も色違いにするか | **しない。** 同時 25 色の契約に 8 色ぶんの車体色は入らない。FC は「自機は黄・ライバルは赤」の 2 行のままにする（ミニマップのマーカーが 2 色なのと同じ理由）。`CAR_SPRITE_GEOMETRY.rows` を世代ごとの値にする |
| D-3 | R-2 の重ね順と走査線制限の優先度を分けるか | **分けない。Y 順が優先度順でもある**（実機のスプライト番号は優先度と重なりの両方を決める）。走査線制限はいま 1 件も効いていない（§2.2）ので、自機が消える心配はない。将来効き始めたら「自機だけ先頭」を例外として入れる |
| D-4 | R-2 は第1世代にも入れるか | **入れる。** 同じ `sprite-plane.ts` / `car-sprite.ts` の欠陥で、FC でも 7.5 % のフレームが逆順になっている。直す場所は 1 か所 |
| D-5 | R-3 の車体形状 | **トラック空間の軸並行矩形**（前後 `CAR_LENGTH` × 左右 `CAR_WIDTH`）。ヨー角は無視する。AI の操舵が生む姿勢角は最大でも 0.3 rad 程度で、矩形の回転を入れても接触判定はほとんど変わらないのに、決定性の検証は難しくなる |
| D-6 | R-3 の応答 | **最小移動量（重なりの浅い軸）で押し離し、相対速度の一部を失わせる**。追突（前後方向）は closing 速度を大きく削り、並走の擦り（左右方向）は小さく削る。跳ね返り係数は 0（完全非弾性）＋ 追加の損失。**「ゴム紐」も「弾き飛ばし」も入れない** |
| D-7 | 車の寸法をどこに置くか | **`sim/vehicle.ts` に 1 つだけ置く**（`CAR_LENGTH` = 4.2 m / `CAR_WIDTH` = 1.95 m）。衝突（sim）も 3D モデルの倍率（view）も 2D スプライトの `cellMeters` もこの 1 つを参照し、**4 世代で車の実寸が一致する**ことをテストで固定する |
| D-8 | R-4 のタイヤ壁をどこに置くか | **壁の位置（`halfWidth + RUNOFF`）へ移す。** いまの `halfWidth + 3` に当たり判定を足すと、**タイヤ壁の外側（3〜15 m）へ出た車が戻れなくなる** — フェーズ 9-1 が「戻れない地点は 1 つも無い」を保証しているので、これは要求どおりでも受け入れられない。実際のサーキットでもタイヤバリアは壁の内貼りである（§9-3 で確定） |
| D-9 | R-4 の壁の位置ずれ（§2.4 の 1.2 m） | **描かれる壁をシムへ合わせる**（メッシュの草地を 9 → 7.8 m）。シムが唯一の真実であり、9-1 の復帰の実測値（壁ぎわ 2.53 秒ほか）をそのまま保てる。コースメッシュ（第3・第4世代 × 8 セクター）を焼き直す |
| D-10 | R-4 の「大幅減」の量 | **掠りにも下限の損を入れる**（速度の 8 %）。激突（−41 m/s）は既に十分なので上限は据え置き、材質で差を付ける — コンクリートは硬く弾き、タイヤは深く沈んでよく殺す。**復帰時間が 9-1 の実測から 20 % 以上悪化しないこと**を上限の制約にする |
| D-11 | R-5 をカメラで解決するか、モデルの寸法で解決するか | **モデルを実寸にしてカメラを引き直す**（§4.6 に実測の比較）。カメラを詰める案では、同じ大きさに見せるのに `BEHIND` を 2.5 m まで縮める必要があり、屋根が画面の行 197（下端 82 %）まで下がるうえ、**ライバルも小さいままなのでミニカーのレースに見える** |
| D-12 | R-6 の巡回モードから抜ける条件 | **何か操作があったら即座に抜け、無操作の計測をやり直す。** 巡回は `title` 画面だけ。抜けた時点の世代はそのまま（勝手に第1世代へ戻さない） |
| D-13 | R-7 の「モアレ」は何を指すか | **蛍光体マスク（`uMask`）と走査線（`uScanline`）の両方**（§9-1 の回答が (b)）。マスクの 3 画素周期が主な源だが、走査線も表示側の画素格子と干渉して縞に見えることがあるので、**「モアレ OFF」は画素周期の模様をまとめて消す**設定とする。エンジンが走査線の太さを整数丸めしている（§2.7）のは「本ごとの太さの揺れ」を消すためで、縞そのものが消えるわけではない |
| D-14 | R-7 の「フラットディスプレイ」は何を指すか | **樽型歪み（`uCurvature`）を 0 にする。** 名前どおり「画面が平ら」になる。走査線・にじみ・ビネットは残す（それらは平面パネルの CRT フィルタでも普通に出す絵作りである）。**走査線を切るのはモアレ側の役目**で、2 つの設定は重ならない |
| D-15 | R-7 の操作と置き場所 | **専用キー（F / M）でどの画面でも切り替わる**（世代切替と同じ扱い）。現在値はポーズ画面とタイトルの操作説明に出す。設定の永続化（localStorage）は入れない（§9-2 で確定） |

## 4. 設計

### 4.1 車の寸法を 1 つにする（D-7・R-3 / R-5 の土台）

```ts
// sim/vehicle.ts
export const VEHICLE = {
  …
  /** 車体の全長 [m]。衝突判定・3D モデルの倍率・スプライトの世界寸法が共有する唯一の値 */
  CAR_LENGTH: 4.2,
  /** 車体の全幅 [m]。2D スプライトの実測（1.95 m）に合わせてある */
  CAR_WIDTH: 1.95,
};
```

| 参照する側 | いまの値 | 変更後 |
| --- | --- | --- |
| `sim/collision.ts`（新規） | — | `CAR_LENGTH` / `CAR_WIDTH` |
| `view/shared/car-model.ts` | 倍率なし（幅 0.865 m） | `CAR_WIDTH / bodyWidth` 倍 |
| `view/shared/car-sprite.ts` | `cellMeters` 3.08 / 3.01（結果として 1.95 m） | 据え置き。**テストで 1.95 m と一致することを固定** |
| `view/gen4-ps2.ts` の落ち影 | `SHADOW_HALF` 0.5 | `CAR_LENGTH / 2`（≒ 2.1）から導く |

### 4.2 第2世代のパレット替え（R-1）

`tools/build-car-sprites.mjs` を拡張する。第1世代の出力は**1 バイトも変えない**。

1. ライバル行（赤）の絵を **16 色へ量子化**する（メディアンカット・RGB555 の格子へ丸め）。
   得られるのは「インデックス地図（128 × 384）」と「基準パレット（16 色）」
2. パレットの各色を**車体色**（彩度 > 0.35）と**共有色**（タイヤ・窓・影・ヘッドライト）に分ける。
   実測では彩度の高い画素が 56 % を占め、そこに 60 色が使われている（§2.1）ので、
   量子化後は概ね **車体 6〜8 色 ＋ 共有 8〜10 色** に落ちる
3. `ENTRANT_COLORS[k]` ごとに、車体色の**明度と彩度の比を保ったまま色相だけを移す**。
   共有色は 8 パレットで同一にする
4. 8 行（`entrant` 0..7）を縦に並べた 384 × 1024 のアトラスを焼く

```ts
// view/shared/car-sprite.ts
export const CAR_SPRITE_GEOMETRY = defineGenerationVariant({
  FC:  { columns: 3, rows: 2, cell: 128, … },   // 自機（黄）／ライバル（赤）
  SFC: { columns: 3, rows: 8, cell: 128, … },   // エントラントごとに 1 パレット
  …
});

/** その車が使う行。パレット替えを持たない世代は自機／ライバルの 2 行に落とす */
export function spriteRowFor(atlas: CarSpriteAtlas, entrant: number): number {
  return atlas.perEntrant ? entrant : entrant === 0 ? 0 : 1;
}
```

**色数の予算**: 共有色 10 ＋ 車体色 8 台 × 7 = **66 色以内**に収める。
画面の同時色数（実測 207 / 256）に対し、いまの車 2 行（235 色のアトラス）より減る見込みで、
`Docs/QUALITY_REVIEW.md` §2 の「256 色以内」は 11-1 の後に測り直す。

### 4.3 重ね順を Y でそろえる（R-2・D-3 / D-4）

`sprite-plane.ts` に「積む順を決めるのは登録順ではなく Y」という規則を持たせる。

```ts
// 変更前: 登録順の逆に積む（＝先頭が最前面）
for (let index = limited.visible.length - 1; index >= 0; index--) …

// 変更後: 画面 Y の昇順に積む（上＝奥が先、下＝手前が後）。
// 走査線制限は従来どおり「登録順＝優先度」で掛ける
const painted = [...limited.visible].sort((a, b) => (a.y + a.height) - (b.y + b.height));
for (const entry of painted) for (const sprite of entry.sprites) frame.sprites.push(sprite);
```

- 比較するのは**接地線**（`y + height`）にする。中心や上端で比べると、大きさの違う 2 台が
  同じ地面に居るときに前後が入れ替わる
- `rivalPlacements()` の並べ替え（距離の降順）と「近い車が後に描かれる」というコメントは、
  この規則に一本化する。**自機もライバルと同じ 1 本の並びに入る**
- ミニマップのマーカー（`NO_ENTITY`）は車と混ぜない。従来どおり `background` /
  マーカー専用の並びに置き、Y 順の対象から外す

### 4.4 車どうしの衝突（R-3・D-5 / D-6）

新規 `src/game/sim/collision.ts`。`stepRace()` が**全車を進めたあとに 1 回だけ**呼ぶ。
1 台ずつの `stepVehicle` の中で解くと、更新順が結果を変えてしまう。

```ts
const CONTACT = {
  /** 追突で失う closing 速度の割合。0.5 が完全非弾性（等質量）*/
  REAR_ABSORB: 0.5,
  /** 追突で「両者が」余分に失う割合。要求の「速度が落ちる」がこれ */
  REAR_LOSS: 0.35,
  /** 並走の擦りで失う速度 [m/s per (m/s of 横方向の相対速度)] */
  SIDE_LOSS: 0.5,
  /** 押し離したあとに残す隙間 [m] */
  SEPARATION: 0.02,
} as const;
```

```
for each pair (a, b) in index order:
  ds = track.deltaS(a.s, b.s); dl = a.lateral - b.lateral
  overlapS = CAR_LENGTH - |ds|;  overlapL = CAR_WIDTH - |dl|
  if overlapS <= 0 or overlapL <= 0: continue

  if overlapS < overlapL:                      // 前後の接触（追突）
     後ろの車 = ds < 0 ? a : b
     closing = 後ろの前進速度 - 前の前進速度
     if closing > 0:
        後ろ -= (REAR_ABSORB + REAR_LOSS) * closing
        前   += (REAR_ABSORB - REAR_LOSS) * closing   // 押されるが、合計の運動量は減る
     s を overlapS/2 ずつ離す
  else:                                        // 左右の接触（擦り）
     lateral を overlapL/2 ずつ離す
     両車 -= SIDE_LOSS * |横方向の相対速度|
     互いに離れる向きへ yaw をわずかに寄せる
  接触した車に hitKind = 'car' と hitStrength（失った速度 [m/s]）を立てる
```

- **速度は負にしない**。`Math.max(0, …)` を通す
- 完走した車（`finished`）とカウントダウン中は判定しない
- `hashRaceState()` は変更しない（`speed` と `s` に必ず現れる）
- AI 側は既に前方回避（`AVOID_AHEAD` 26 m）を持っているので、**AI の変更はしない**。
  接触が増えて目標タイムが崩れるかどうかは 11-8 で測る

### 4.5 壁の材質と衝突音（R-4・D-8 / D-9 / D-10）

**壁の位置を 1 つにする**（D-9）。`sim/vehicle.ts` に

```ts
/** 壁の位置（中心線からの距離）[m]。メッシュ生成ツールもここを読む */
export function wallLateral(halfWidth: number): number { return halfWidth + VEHICLE.RUNOFF; }
```

を置き、`tools/build-track-mesh.mjs` の `GRASS_WIDTH = 9` を
`VEHICLE.RUNOFF - CURB_WIDTH`（＝ 7.8 m）へ変えて焼き直す。

**材質**は弧長から引く。タイヤ壁が立っている区間（高曲率区間）は `'tyre'`、それ以外は
`'concrete'`。判定表は背景オブジェクトと同じ 1 つの定義から作るので、**見えているタイヤ壁と
当たり判定が構造的にずれない**。

```ts
// sim/scenery.ts（view/shared/scenery.ts から配置の表だけを移す）
export type WallMaterial = 'concrete' | 'tyre';
export function wallMaterialAt(track: Track, s: number, side: -1 | 1): WallMaterial;
```

> **`scenery.ts` を `view/` から `sim/` へ移すのは、シムが view を import しないため**である
> （不変条件）。配置は `s` と `curvature` だけから決まる決定論的な表で、もともと
> 「4 世代 ＋ 生成ツールが読む 1 つの真実」なので、置き場所は `sim/` のほうが正しい。
> view 側は import 元が変わるだけで中身は変わらない。

**当たりの強さ**（`stepVehicle` の壁の分岐）:

```ts
const WALL = {
  concrete: { bite: 1.8, minimumLoss: 0.08, bounce: 0.4 },   // いまと同じ噛み方 + 下限
  tyre:     { bite: 3.0, minimumLoss: 0.14, bounce: 0.8 },   // 深く沈んでよく殺す
};
speedLoss = max(outward * bite, speed * minimumLoss)
```

`hitKind` は `'concrete' | 'tyre' | 'car' | 'none'`、`hitStrength` は失った速度 [m/s]。
既存の `hitWall: boolean` は `hitKind !== 'none' && hitKind !== 'car'` の派生として残すか、
読み手（`sfx.ts` と `vehicle-recovery.spec.ts` の 3 か所だけ）を書き換える。

**音**（`audio/sfx.ts`）。3 種類とも `playOneShot` を通るので、**世代が変われば音色も変わる**。

| 何に当たったか | role | 音の作り | 強さ |
| --- | --- | --- | --- |
| コンクリート壁 | `perc` | 78 Hz・0.30 s（いまの `IMPACT`） | `hitStrength` に比例 |
| タイヤ壁 | `perc` | 55 Hz・0.22 s（低く・短く ＝ 沈む） | 同上 |
| 車 | `fx` | 220 Hz・0.12 s（金属質の軽い当たり） | 同上 |

強さを**自車速度ではなく実際に失った速度から**決めるので、掠りは小さく、激突は大きく鳴る。

### 4.6 第3・第4世代の車を実寸にする（R-5・D-11）

倍率はモデルの実測幅から導く（値を手で書かない）。

| 世代 | モデルの幅 | 倍率（= 1.95 / 幅） | 全長になる値 | 車高になる値 |
| --- | --- | --- | --- | --- |
| PS1 | 0.865 m | **2.2546** | 4.24 m | 1.08 m |
| PS2 | 0.881 m | **2.2137** | 4.22 m | 1.10 m |

`CAR_GROUND_OFFSET`（0.25）と第4世代の影の半径（`SHADOW_HALF` 0.5）も同じ倍率で伸びる。

**カメラを引き直す。** 実寸のままいまのカメラだと車体が画面幅の 71 % を占め、
30 m 先の路面が屋根の 10 px 上にしか残らない。速度 40 m/s・PS1 で投影して測った候補:

| BEHIND | HEIGHT | 車幅（画面比） | 屋根の行 / 240 | 30 m 先の路面の行 |
| --- | --- | --- | --- | --- |
| 現状（3.2 / 1.25・モデル等倍） | | 18 % | 161 | 117 |
| 4.5 | 1.6 | 46 % | 143 | 114 |
| 5.0 | 1.6 | 38 % | 138 | 115 |

### 4.7 タイトルのアトラクト（R-6・D-12）

状態を持つのは「無操作が何ティック続いたか」と「いまの世代を何ティック見せたか」の 2 つだけ。
`flow/` に純粋な関数として置き、`module.ts` から呼ぶ。

```ts
// flow/attract.ts（新規）
export const ATTRACT = {
  /** これだけ無操作が続いたら世代の巡回を始める [s] */
  IDLE_SECONDS: 5,
  /** 1 世代を見せる長さ [s] */
  GENERATION_SECONDS: 5,
} as const;

export interface AttractState { idleTicks: number; showTicks: number; cycling: boolean }
export function createAttract(): AttractState;

/** 1 ティック進める。戻り値が真なら「次の世代へ」 */
export function stepAttract(
  state: AttractState,
  input: { readonly onTitle: boolean; readonly anyInput: boolean },
): boolean;
```

- `anyInput` は `context.input.snapshot`（`keys` / `gamepadButtons` / `gamepadAxes`）から作る。
  **アクションに割り当てていないキーでも「操作あり」とみなす**（放置の判定なので広く採る）
- `onTitle` が偽になったら状態を畳む（レース中は巡回しない）
- 世代の送りは `context.generation.cycle(1)`。**巡回も手動の Q / E と同じ経路**を通るので、
  切替演出も BGM の位相保存も追加のコストが無い
- 5 秒周期のうち 350 ms（7 %）は 2 世代を描く切替フレームになる。負荷は既存の切替と同じ

デモの作り直し（`race.phase === 'finished'` → `newRace`）は既にあるので、
**テストで固定するだけ**にする。**シードは変えない**（§9-4 で確定）ので、デモは同じレースを
繰り返す — 「タイトルを眺めた長さがレースの内容を変えない」という既存の不変条件
（`flow.spec.ts`）をそのまま保てる。

### 4.8 画面モード（R-7・D-13 / D-14 / D-15）

```ts
// view/shared/screen-mode.ts（新規）
export interface ScreenMode {
  /** 真なら樽型歪みを 0 にする ＝ 平面パネル */
  flatDisplay: boolean;
  /** 偽なら蛍光体マスクと走査線を 0 にする ＝ 画素周期の模様を消す（D-13） */
  moire: boolean;
  toggleFlatDisplay(): void;
  toggleMoire(): void;
  /** レンダラーへ毎フレーム渡す上書き。既定（両方 ON のまま）では空 */
  crtOverride(): Partial<CrtPreset>;
}
```

| 設定 | 既定 | 上書き |
| --- | --- | --- |
| フラットディスプレイ | OFF（＝ブラウン管の丸みあり・いまの見え） | ON のとき `{ curvature: 0 }` |
| モアレ | ON（＝走査線と蛍光体マスクあり・いまの見え） | OFF のとき `{ mask: 0, scanline: 0 }`（D-13） |

2 つは独立しているので、上書きは**単純な合成**で足りる。

```ts
crtOverride() {
  return {
    ...(this.flatDisplay ? { curvature: 0 } : {}),
    ...(this.moire ? {} : { mask: 0, scanline: 0 }),
  };
}
```

両方切ると、残るのは にじみ・ブルーム・ビネット・ざらつき ＝ **平面パネルに映した素の絵**になる。

**既定は「いまの見え方」**にする。初回起動の絵が変わらないことが、この機能の受け入れ条件でもある。

配線:

```
main.ts ── createScreenMode() ──┬── boot({ …, screenMode })      → renderer の crtOverride
                                └── createRacingModule({ screenMode }) → キー入力と表示
```

- `racingModule`（定数）を `createRacingModule(options)`（関数）へ変える。
  現状 `module.ts` はアプリ側の値を受け取る口を持っていないため
- 開発時の `?crt=off` は従来どおり全項目 0 の上書きで、こちらが優先（計測用の口）
- 入力は `toggleFlat`（`KeyF`）/ `toggleMoire`（`KeyM`）を `ACTIONS` に足す。
  `main.ts` の `swallowed` にも足す（ブラウザの既定動作に食われないように）
- 表示はポーズ画面に 1 行足す — `F: FLAT [ON]   M: MOIRE [OFF]`。
  タイトルの操作説明にも 1 行（`F FLAT  M MOIRE`）を足す

### 回答で変わった点

**9-1 の (b) だけが計画初版の想定（(a)）と違う。** 走査線は「モアレ対策として太さを整数へ
